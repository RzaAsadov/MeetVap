MeetVap Docker installation and operations

A complete guide for deploying, updating, backing up, monitoring, and troubleshooting a standalone MeetVap child server.

Git installationArchive installationFour domainsAutomatic migrations

Overview

The bundle runs the API server, admin panel, web client, meeting client, LiveKit, PostgreSQL, Redis, nginx, and Certbot on one Docker host.

Web

https://WEB_DOMAIN, served directly by nginx.

Meet

https://MEET_DOMAIN, served directly by nginx.

API and signaling

https://SERVER_DOMAIN and wss://SERVER_DOMAIN/rtc.

Admin

https://ADMIN_DOMAIN on its own hostname.

PostgreSQL and Redis are private Docker services. Persistent named volumes keep database data, Redis state, uploads, certificates, and ACME files.

Requirements

  • A Linux VPS with a public IPv4 address.
  • Recommended minimum: 2 CPU cores, 4 GB RAM, and sufficient upload storage.
  • Docker Engine and the Docker Compose plugin.
  • Four DNS hostnames pointing to the VPS.
  • Root or sudo access.

Install Docker

For production, install Docker Engine and Compose from the official Docker repository instructions. A common quick installation on a clean VPS is:

curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
rm get-docker.sh
sudo systemctl enable --now docker
sudo usermod -aG docker "$USER"

Log out and back in after changing group membership, then verify:

docker --version
docker compose version
sudo systemctl is-enabled docker

DNS and firewall

Create four DNS A records pointing to the VPS public IP: web, meet, server/API, and admin. The server/API hostname must not be proxied through a CDN that cannot carry LiveKit WebSockets and WebRTC traffic.

PortProtocolPurpose
80TCPLet's Encrypt validation and HTTPS redirect
443TCPHTTPS, API, web clients, admin, WebSocket signaling
3478UDPTURN UDP
5349TCPTURN TLS
7881TCPLiveKit TCP fallback
7882UDPPrimary LiveKit media
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 3478/udp
sudo ufw allow 5349/tcp
sudo ufw allow 7881/tcp
sudo ufw allow 7882/udp
sudo ufw reload
Cloud firewallOpen the same ports in GCP, AWS, or the VPS provider firewall. Use ingress rules targeting this VM. Port 4000, PostgreSQL, and Redis must not be public. The old UDP range 50000-60000 is not used by this configuration.

Option A: Git repository

Use this path when you have access to the MeetVap Docker deployment repository. Required application images are downloaded automatically.

git clone <docker-deployment-repository> meetvap-docker
cd meetvap-docker
./install.sh

If you were given credentials for a private container registry, authenticate first:

docker login ghcr.io

The installer asks for four domains, main server host, child relay key, admin username, and a minimum 12-character admin password. It generates database, JWT, session, internal-event, and LiveKit secrets; starts PostgreSQL and Redis; applies all Prisma migrations; obtains one certificate for all four domains; and starts the services.

Before installationCreate the child entry in the main server's Admin → Sub-domains section, copy its relay key, and whitelist the child VPS public origin IP.

Option B: supplied installation archive

Use this path when you received a meetvap-local-build.tar.gz installation archive instead of repository access.

Upload the archive

scp /path/to/meetvap-local-build.tar.gz user@your-vps:/tmp/

On the VPS

sudo mkdir -p /opt/meetvap-build
sudo chown "$USER":"$USER" /opt/meetvap-build
tar -xzf /tmp/meetvap-local-build.tar.gz -C /opt/meetvap-build
cd /opt/meetvap-build/docker
./install.sh --local-images

The installer builds the supplied MeetVap package on the VPS. The nginx image includes the web and meet applications. Required third-party Docker images are downloaded automatically.

Configuration and generated files

Private installation state is stored in docker/.env, docker/generated/, and docker/secrets/. Protect these paths and include them only in secure backups.

FilePurpose
.envDomains, generated secrets, image names, and selected version.
generated/config.jsonChild role, main server relay, retention, limits, and policy.
generated/admin-config.jsonAdmin login, session secret, database URL, API URL.
generated/livekit-servers.jsonPublic client URL and private Docker health URL.
generated/livekit.yamlLiveKit, Redis, TURN, ports, and TLS files.
generated/nginx.confFour HTTPS virtual hosts and proxy routing.
generated/runtime-config.jsAPI URL used by web and meet builds.
generated/server-optional.envApp Attest identifiers and optional store-purchase verification variables.
Correct LiveKit URL modelClients receive wss://SERVER_DOMAIN. API and admin health checks use http://livekit:7880. The private health URL is intentional and must not be changed to the public domain.

Initial database

The installer runs prisma migrate deploy before application startup. No SQL dump is required. Later updates apply only pending migrations.

Updating

Git repository installation

cd /path/to/meetvap-docker
git pull
./update.sh

Set MEETVAP_VERSION in .env to an immutable release tag or use latest. The script pulls images, applies migrations, and replaces application containers without deleting named volumes.

Archive installation

Obtain the updated installation archive, transfer it, and extract it over the existing build directory. Do not delete docker/.env, generated, secrets, or backups.

# Administrator workstation
scp /path/to/meetvap-local-build.tar.gz user@your-vps:/tmp/

# VPS
tar -xzf /tmp/meetvap-local-build.tar.gz -C /opt/meetvap-build
cd /opt/meetvap-build/docker
./update.sh

The update script rebuilds the supplied application package, applies database migrations, and replaces the application containers.

Backup and restore

cd /path/to/meetvap/docker
./backup.sh
ls -lah backups/

A backup contains a PostgreSQL dump, uploaded files, .env, and generated runtime configuration. Copy the resulting directory to separate storage.

./restore.sh backups/20260807T120000Z
Restore replaces dataThe restore process replaces the current database and uploaded files. It requires typing RESTORE. Take a fresh backup first.

Routine operations

cd /path/to/meetvap/docker
docker compose ps
docker compose logs --tail=200 server
docker compose logs -f server admin livekit nginx
docker compose restart server
docker compose restart livekit
docker compose up -d

Rebooting the VPS

Core services use restart: unless-stopped. Do not run docker compose down before rebooting.

sudo systemctl enable docker
sudo reboot

# After reconnecting
cd /path/to/meetvap/docker
docker compose ps
docker compose logs --since=5m postgres redis server admin livekit nginx

Reserve a static cloud IP. A normal reboot normally retains an ephemeral IP, but stopping and starting a VM can change it.

TLS certificates

Certbot checks renewal every 12 hours. Nginx validates and reloads every 6 hours, so HTTPS adopts renewed files automatically.

docker compose ps certbot-renew
docker compose logs --tail=100 certbot-renew
docker compose exec certbot-renew certbot renew --dry-run --webroot -w /var/www/certbot
TURN certificateLiveKit reads the TURN TLS certificate when it starts. After an actual renewal, run docker compose restart livekit. Port 80 and all four DNS records must remain available for renewal.

Call troubleshooting

docker compose ps livekit
docker compose port livekit 7881
sudo ss -lntup | grep -E ':(3478|5349|7881|7882)\b'
docker compose exec -T server node -e \
"fetch('http://livekit:7880').then(r=>console.log(r.status)).catch(console.error)"

For one controlled failed call, temporarily set logging.level: debug in generated/livekit.yaml, restart LiveKit, then collect:

docker compose logs --since=1m -f server livekit nginx 2>&1 | tee /tmp/call-debug.log
sudo tcpdump -ni any '(udp port 7882 or udp port 3478 or tcp port 5349 or tcp port 7881)'
  • Expect issue-token-ready for both users.
  • Expect both participants in the same room.
  • Expect bidirectional UDP 7882 or fallback/TURN traffic.
  • If config or certificates changed, restart LiveKit before deeper investigation.

Return logging to info after testing.

Security and child-server behavior

  • This deployment is configured as serverRole: child.
  • The child stores device tokens but relays push requests to the main server.
  • Do not copy FCM or APNs provider credentials to the child.
  • Keep .env, generated files, relay keys, LiveKit credentials, and backups private.
  • Expose only the documented ports. Database, Redis, API port 4000, admin port 4300, and LiveKit port 7880 remain internal.

The installer configures the non-secret App Attest identifiers in generated/server-optional.env. Keep development attestations disabled on production servers. Optional Google Play and Apple purchase-verification credentials can be mounted under secrets/ and referenced from the same file.

Stopping or resetting

# Stop while preserving data
docker compose stop

# Start again
docker compose up -d

# Permanently remove this deployment and all its Docker volumes
docker compose down --volumes --remove-orphans --rmi all
rm -rf generated .env
Permanent deletionThe reset command deletes PostgreSQL, Redis state, uploads, and certificates stored in this deployment's named volumes. Back up first.

Обзор

Комплект запускает API, панель администратора, веб-клиент, клиент встреч, LiveKit, PostgreSQL, Redis, nginx и Certbot на одном Docker-хосте.

Web

https://WEB_DOMAIN, файлы отдает nginx.

Meet

https://MEET_DOMAIN, файлы отдает nginx.

API и сигнализация

https://SERVER_DOMAIN и wss://SERVER_DOMAIN/rtc.

Admin

https://ADMIN_DOMAIN на отдельном домене.

PostgreSQL и Redis доступны только во внутренней Docker-сети. Именованные тома сохраняют базу, Redis, загрузки, сертификаты и ACME-данные.

Требования

  • Linux VPS с публичным IPv4.
  • Рекомендуемый минимум: 2 ядра, 4 ГБ RAM и достаточное место для загрузок.
  • Docker Engine и плагин Docker Compose.
  • Четыре DNS-имени, направленные на VPS.
  • Доступ root или sudo.

Установка Docker

Для production установите Docker Engine и Compose по официальной инструкции Docker. Быстрая установка на чистом VPS:

curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
rm get-docker.sh
sudo systemctl enable --now docker
sudo usermod -aG docker "$USER"

Выйдите и войдите снова, затем проверьте:

docker --version
docker compose version
sudo systemctl is-enabled docker

DNS и сетевой экран

Создайте четыре DNS-записи A: web, meet, server/API и admin. Все должны указывать на публичный IP VPS. Домен API не должен проксироваться через CDN, который не поддерживает LiveKit WebSocket и WebRTC.

sudo ufw allow 443/tcp

Вариант A: Git-репозиторий

Используйте этот способ, если у вас есть доступ к Docker-репозиторию развертывания MeetVap. Необходимые образы приложений будут загружены автоматически.

git clone <docker-deployment-repository> meetvap-docker
cd meetvap-docker
./install.sh

Если вам выданы данные доступа к приватному реестру контейнеров, сначала выполните:

Установщик запросит четыре домена, адрес главного сервера, relay key дочернего сервера, логин администратора и пароль минимум из 12 символов. Он создаст секреты, запустит PostgreSQL и Redis, применит Prisma-миграции, получит общий TLS-сертификат для четырех доменов и запустит сервисы.

До установкиСоздайте запись дочернего сервера в Admin → Sub-domains главного сервера, скопируйте relay key и добавьте публичный IP дочернего VPS в белый список.

Приватное состояние хранится в docker/.env, docker/generated/ и docker/secrets/. Никогда не публикуйте эти пути.

Начальная база данных

Установщик выполняет prisma migrate deploy. SQL dump для первой установки не нужен. При обновлениях применяются только новые миграции.

Перезагрузка VPS

Основные сервисы используют restart: unless-stopped. Не выполняйте docker compose down перед перезагрузкой.

sudo systemctl enable docker
sudo reboot

# После повторного входа
cd /path/to/meetvap/docker
docker compose ps
docker compose logs --since=5m postgres redis server admin livekit nginx

Закрепите статический облачный IP. Обычная перезагрузка обычно сохраняет временный IP, но остановка и новый запуск VM могут его изменить.

TLS-сертификаты

Certbot проверяет продление каждые 12 часов. Nginx проверяет конфигурацию и перезагружается каждые 6 часов, поэтому HTTPS автоматически подхватывает новые файлы.

docker compose ps certbot-renew
docker compose logs --tail=100 certbot-renew
docker compose exec certbot-renew certbot renew --dry-run --webroot -w /var/www/certbot
Сертификат TURNLiveKit читает TLS-сертификат TURN при запуске. После реального продления выполните docker compose restart livekit. Порт 80 и DNS всех четырех доменов должны оставаться доступными.

Диагностика звонков

docker compose ps livekit
docker compose port livekit 7881
sudo ss -lntup | grep -E ':(3478|5349|7881|7882)\b'
docker compose exec -T server node -e \
"fetch('http://livekit:7880').then(r=>console.log(r.status)).catch(console.error)"

Для одного контролируемого сбоя временно установите logging.level: debug в generated/livekit.yaml, перезапустите LiveKit и соберите:

docker compose logs --since=1m -f server livekit nginx 2>&1 | tee /tmp/call-debug.log
sudo tcpdump -ni any '(udp port 7882 or udp port 3478 or tcp port 5349 or tcp port 7881)'
  • Должен появиться issue-token-ready для обоих пользователей.
  • Оба участника должны войти в одну комнату.
  • Должен идти двусторонний UDP 7882 либо fallback/TURN-трафик.
  • После изменения конфигурации или сертификата сначала перезапустите LiveKit.

После проверки верните уровень info.

Безопасность и режим child

  • Развертывание использует serverRole: child.
  • Child хранит device tokens, но передает push-запросы главному серверу.
  • Не копируйте FCM и APNs provider credentials на child.
  • Храните .env, generated-файлы, relay keys, LiveKit credentials и backups приватно.
  • Открывайте только документированные порты. PostgreSQL, Redis, API 4000, admin 4300 и LiveKit 7880 остаются внутренними.

Установщик записывает публичные идентификаторы App Attest в generated/server-optional.env. На production-серверах не включайте development attestations. Необязательные данные проверки покупок Google Play и Apple можно разместить в secrets/ и указать в том же файле.
